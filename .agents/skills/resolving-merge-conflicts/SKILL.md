# 解决 Git 冲突

先确认正在进行的 Git 操作、冲突文件和冲突前工作区状态。读取双方改动及其来源，理解每一侧试图达成的行为；不要仅凭 ours/theirs、行数或文件较新来决定。

## 处理方式

- 意图明确且可验证的冲突可以直接合并，例如无关新增内容、重复 import 或兼容的独立配置。
- 双方行为互斥、影响公开 API/数据兼容、删除意图不清或证据矛盾时，向用户说明双方目的、可选结果、影响和推荐方案，并展示最小必要差异。问题应按语义决策组织，避免逐行机械询问。
- 用户回答前继续处理不依赖该决定的冲突；受该决定影响的文件保持待定。
- 不预设必须完成所有冲突，也不预设必须 abort。继续、abort、提交、推送或强制推送均遵循当前任务授权。
- 保留冲突前已有的 staged/unstaged 意图。只暂存本次解决的文件，不使用 `git add -A`。

按当前仓库规则执行必要的冲突相关验证，并分别报告解决结果、验证证据和仍待决定项。只清除冲突标记不等于语义已解决。
