# Java 模板交付配置迁移

Status: resolved

## Problem Statement

模板仍展示独立交付运行时配置，缺少统一宿主、启动策略和发布签名的完整使用说明，复制模板后容易沿用过期构建约定。

## Solution

让 Java 模板展示可直接使用的统一宿主交付配置，复用项目应用信息，明确开发构建与发布签名，并提供本模板自己的验证与排错说明。

## User Stories

1. As a 模板使用者, I want 复制后运行 Java 示例, so that 验证开发环境
2. As a 脚本作者, I want 沿用项目包名、名称、版本和图标, so that 只维护一份应用信息
3. As a 脚本作者, I want 配置统一宿主来源及本地覆盖, so that 选择需要的构建输入
4. As a 脚本作者, I want 选择自动或手动启动, so that 控制安装后的体验
5. As a 开发者, I want 通过设备构建交付 APK, so that 验证示例可交付
6. As a 发布者, I want 配置可复用签名及秘密注入, so that 持续发布同一应用
7. As a 开发者, I want 明确区分开发签名与发布签名, so that 避免误用
8. As a 脚本作者, I want 自行决定是否提供宿主导航按钮, so that 控制界面
9. As a 模板使用者, I want 看到本语言的构建及排错说明, so that 独立完成使用
10. As a 模板使用者, I want 保留初始化、语言依赖与入口约定, so that 迁移后仍能正常运行

## Implementation Decisions

- 仅更新本 Java 模板自己的配置、示例和用户文档。
- 移除旧交付运行时配置，采用统一宿主配置；不保留兼容别名。
- 应用信息继续取自现有项目配置，启动策略显式可配置。
- 开发示例可使用开发签名；发布示例引用用户密钥，秘密从本地或环境注入，不提交真实密钥或密码。
- 保留语言入口、初始化脚本、依赖和资源布局，不能为统一交付误删语言特有内容。
- 不默认增加宿主管理按钮；必要示例说明作者可自行通过 Navigation 使用宿主页面。
- 文档只描述本模板公开配置、使用步骤及预期结果。

## Testing Decisions

- 通过本模板真实 Java DSL 配置、生成和构建验证，不能只检查文本字段。
- 验证默认运行与 APK 交付，检查名称、包名、版本、图标及启动策略。
- 验证发布签名配置及缺失诊断，检查生成载荷不包含秘密。
- 实际安装启动验证语言入口和初始化仍有效；环境无法观察的行为记录为证据缺口。

## Out of Scope

不维护共享构建实现，不新增脚本 API 或通用打包器，不将其他模板的文档集中到本仓库。

## Further Notes

本模板作为公开配置的使用示例，最终验收要求示例能实际执行。
