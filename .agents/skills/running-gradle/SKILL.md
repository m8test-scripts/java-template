# 运行 Gradle

先从仓库根目录使用项目 Wrapper，并确认目标任务及它的实际范围。用户只要求 IDE/Gradle sync 时选择配置或帮助任务，不扩大为编译、测试或设备操作。

- 一次只运行一个由本会话启动的 Gradle 命令，结束后再启动下一个；不管理、不停止其他会话、IDE 或开发者启动的进程。
- 使用 `-q`，限制为一个 worker，并按机器和项目需要限制 JVM 内存。设置内存时保留项目必需的 JVM 参数，不无意覆盖现有参数。
- 不使用 debug 全量日志。只返回失败摘要、定位错误所需上下文和退出状态；成功时简要报告任务与结果。
- 设备、安装或发布任务仅在用户请求或当前授权流程需要时执行，并遵循仓库规定的设备选择方式。
- 失败时先检查相关任务和错误附近日志，再决定是否查看更详细堆栈。
