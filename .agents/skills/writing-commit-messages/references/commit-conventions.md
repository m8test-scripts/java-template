# 中文 Conventional Commit 约定

此约定适用于所有 M8Test 仓库的新提交，不要求重写历史。

## 标题

```text
<type>(<scope>): <中文简短描述>
```

scope 可省略。主要属于单一模块或领域时优先填写；跨领域或不清晰时省略。描述使用直接、具体的动词短语，不以句号结尾，不写实现过程。

## 类型

| type | 用途 |
| --- | --- |
| `feat` | 新增调用方或用户可观察的能力 |
| `fix` | 修复现有行为 |
| `docs` | 文档、领域上下文、ADR 或 Agent 技能 |
| `refactor` | 不改变外部行为的结构调整 |
| `test` | 测试或测试基础设施 |
| `chore` | 维护、工具和一般配置 |
| `build` | 构建系统或依赖 |
| `ci` | 持续集成 |
| `perf` | 性能改进 |
| `style` | 不影响语义的格式或风格调整 |
| `revert` | 回滚已有提交 |

类型表示提交的主要目的。变更可拆分时，按独立目的分别提交。

## 提交范围与验证

- 提交前审查完整 staged diff，只暂存当前提交的文件；不得用 `git add -A` 混入无关修改。
- 保留用户已有 staged/unstaged 改动，不覆盖、清除或重置。
- API、实现、测试和文档确属同一行为切片时可以一起提交；不同根因或不同领域应拆分。
- 至少运行 `git diff --check`，再按改动范围执行定向验证。纯文档/技能变更不需要代码测试，但应执行相关文档或技能校验。
