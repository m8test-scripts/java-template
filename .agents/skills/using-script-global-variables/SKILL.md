# 使用脚本全局变量

## 查找当前项目可用的变量

1. 先查看本模板的 `README.md`、Gradle 插件配置和任务列表，确认语言及其全局变量生成任务。任务通常名为 `generate<Language>GlobalVariables`；以当前项目实际注册的任务为准。
2. 确认 Development Kit 设备连接并可用，然后运行该任务。Gradle 命令使用 `-q`。设备选择方式以项目插件文档和当前设备配置为准。
3. 从本次任务生成的 `build/global` 产物读取变量名与类型。生成结果是当前宿主、已安装 Extension 和项目配置组合的证据；不要用技能文档中的旧清单代替它。
4. 在脚本源码中使用生成文件给出的完整变量名。语言前缀/后缀由语言插件和变量注册配置决定，不能只凭其他语言的习惯推断。
5. 若变量来自宿主接口，继续追踪其类型的公开 API；若来自 Extension，确认当前脚本项目已声明并加载该 Extension。代码补全声明不能证明运行时依赖已加载。

## 生成任务不可用时

检查任务注册和设备端 BuildScript 的 `generateGlobalVariablesJson` 执行链，再检查变量注册源码中公开类型及 prefix/suffix 标志。将这种结论标记为源码推断，并明确没有完成设备端生成验证。若任务报告成功，必须确认新生成文件存在且内容对应当前项目；只有命令退出码为零不足以证明生成结果可用。

生成文件属于构建产物，默认不提交到版本控制。不要把变量全集、某种语言的固定前缀或某台设备的配置复制进本技能；任务失败涉及构建插件或宿主实现时，修复实际责任仓库并重跑生成任务。
